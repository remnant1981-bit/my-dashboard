# 활동 기록 → 시뮬레이션 재보정

등록 후 실제 숫자를 기록해 두면 `simulation/calibrate.py`가 문의율·전환율·패키지 비중을 추정하고, 그 값으로 앞으로의 실수령을 다시 예측함. 지금 `simulation/RESULTS.md`의 숫자는 전부 가정이라, 이 기록이 쌓여야 예측이 의미를 가짐.

## 1. 시작
1. `log_template.csv`를 복사해 `log.csv`로 이름을 바꿈 (엑셀로 열어도 됨, UTF-8 저장 권장. cp949도 읽음)
2. **고객 이름·연락처·사이트 주소 등 개인정보나 의뢰 내용은 적지 않음.** 이 파일은 숫자 집계용임
3. `log.csv`는 `.gitignore`에 있어서 저장소에 올라가지 않음

## 2. 기록 규칙 (한 사건 = 한 행)
| 유형 | 언제 적나 | 패키지 | 판매금액(만원) |
|---|---|---|---|
| 문의 | 문의(견적 요청·채팅)가 올 때마다 1행 | 비움 | 비움 |
| 거절 | 위험(로그인·개인정보·약관) 등으로 내가 거절한 문의. 위 '문의' 행과 **별도로** 추가 | 비움 | 비움 |
| 수주 | 결제(주문)가 들어왔을 때 | **필수** (체험/STANDARD/DELUXE/PREMIUM) | 선택 |
| 재의뢰 | 체험 고객이 상위 패키지를 다시 주문했을 때. **'수주' 행도 함께** 적음 | 선택 | 비움 |
| 완료 | 구매확정(정산 확정)됐을 때 | **필수** | **필수** (고객 결제 금액, 수수료 차감 전) |
| 리뷰 | 리뷰가 달렸을 때 | 선택 | 비움 |

- 날짜는 `YYYY-MM-DD`, 채널은 `크몽`/`숨고`/`기타` 등 자유
- 견적 문의로 가격이 달라진 건은 실제 결제 금액을 적으면 예측에 그대로 반영됨
- 안 A로 등록해 STANDARD 칸에 체험을 넣었다면 패키지는 칸 이름이 아니라 **실제 내용(체험)** 으로 적음

### 예시 (형식 설명용 가상 행, 실제 기록 아님)
```csv
날짜,채널,유형,패키지,판매금액(만원),비고
2026-12-02,크몽,문의,,,
2026-12-03,크몽,문의,,,로그인 필요
2026-12-03,크몽,거절,,,로그인 필요 사이트
2026-12-04,크몽,수주,체험,4,
2026-12-07,크몽,완료,체험,4,
2026-12-08,크몽,리뷰,체험,,
2026-12-20,크몽,수주,DELUXE,15,체험 고객
2026-12-20,크몽,재의뢰,DELUXE,,
```

## 3. 실행
```bash
cd simulation
python calibrate.py ../tracking/log.csv --start 2026-12-01
```
(날짜는 예시. 실제 등록일을 넣을 것)
- `--start`: 상품 등록일 (관측 기간 시작). 생략하면 첫 기록일
- `--until`: 관측 종료일. 생략하면 마지막 기록일 (기록이 없는 최근 며칠을 포함하려면 오늘 날짜를 넣을 것)
- `--weeks 26`: 앞으로 몇 주를 예측할지 / `--target 100`: 목표 누적 실수령(만원)
- `--out ../tracking/report.md`: 리포트 저장

## 4. 결과 읽는 법
- **주의 블록이 먼저 나옴.** 문의 20건·4주 미만이면 추정이 크게 흔들린다는 경고가 뜸. 그 단계에서는 방향만 참고
- 전환율·거절률·재의뢰율은 '실측'과 '예측에 쓴 값'이 따로 나옴. 표본이 작으면 예측에 쓴 값은 기본 가정 쪽으로 당겨짐 (예: 문의 2건에 전환 100%여도 예측에는 약 23%를 씀). 기록이 쌓일수록 실측값에 가까워짐
- 예측은 문의율 하한·추정·상한 3줄로 나옴. 하한~상한 사이 어딘가로 읽을 것
- 기록이 틀리면(필수 칸 누락, 날짜 형식 등) 몇 행이 문제인지 알려주고 멈춤
- 체험 운영 효과(수주 증가)는 리포트의 전환율·패키지 비중을 체험 도입 전후로 나눠 돌려 보면 비교할 수 있음 (`--until`로 구간을 나눔)
